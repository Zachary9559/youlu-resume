01 · 先看这个行业所处的阶段

具身智能这两年融资很活跃，2026 年一季度披露的融资额约 200 亿元、同比增长近 60%。一个明显的变化是，行业对"数据"的重视在上升——机器人能不能真正规模化落地、连续稳定运行，正在成为比"讲故事"更重要的判断标准。

在这个阶段，能拿到真实运营数据、并把它转化成产品和业务迭代的公司，会更有优势。这也是为什么"运营"这件事，在机器人公司里越来越重要。

04 · 这套体系的核心：一级指标 + 二级指标 + 三级指标，以及它们最终支撑的商业结果

我把指标分成四级：一级看运营结果好不好，二级看是什么在驱动它，三级是能持续监控的动作，再往上支撑到商业结果。这样从"结果"到"动作"都能层层定位、归因、优化。

商业结果

为什么这样分层：一级看"结果好不好"，二级看"什么在驱动"，三级看"每天能监控什么"
要让一级结果变好，得知道是哪些二级方向在影响它（运营成功率受任务执行/作业质量/设备健康驱动，满意度受客户体验/服务支撑驱动，日活受设备活跃/安全驱动），再落到三级一个个可监控指标上定位、归因、优化。这样才不是空谈指标，而是真正能建起来、盯得住的体系。
这些指标大部分都能从设备侧直接采到（示例口径）
任务完成率 = 成功完成任务数 ÷ 下发任务数（任务报告 completionPercentage）
覆盖率 = 实际清扫面积 ÷ 计划清扫面积（planned / actualCleaningArea）
机器人日活 = 当日有作业任务的设备台数 ÷ 在网总台数（在线状态 + 任务日志）
用户满意度 = 客户评分均值 或 1 - 投诉率（回访 + 工单）
在线率 = 在线设备台数 ÷ 在网总台数；告警分级 H0-H7、MTTR、耗材剩余%（取 incident / lifeSpan）
回充成功率 = 成功回充次数 ÷ 回充尝试次数；接管率 = 人工接管次数 ÷ 作业总次
数据从哪里来：设备远程监控系统是这套体系的数据底座
以上指标底层都依赖设备侧远程监控：定位地图看覆盖、故障告警看健康、运行数据与报告看任务执行/时长/电量。先保证数据能采到、口径能对上，指标才有意义。
字段参考：高仙开放平台 API（completionPercentage / plannedCleaningArea / incidentLevel / lifeSpan·usedLife）+ 有鹿 AI130 远程运维 App（定位/告警/运行数据与报告）+ 智行者/科沃斯产品页 + 行业做法。注：为示例口径，需与业务方共同校准。
05 · 这类"大脑型"公司，还会有一层"数据飞轮"

有鹿卖的是大脑、靠的是大模型。设备在客户现场运营时产生的真实数据，会回流去训练模型，让模型更强、设备更聪明——这就是数据飞轮。

这个闭环是：运营出数据 → 数据喂模型 → 模型变强 → 设备更聪明 → 运营又更好
设备运营中的失败 case、长尾场景、任务执行记录，都是模型迭代的养料。让数据飞轮转起来，是这类"大脑型"公司区别于传统清洁/配送公司的地方，也是这套体系长期价值所在。
参考：智元"本体-数据-模型-场景"闭环、银河通用、行业"采-治-标-验-训-反馈"数据链路等。
06 · 如果来做，我大概会这样入手
1. 先对齐一级与二级指标的定义和口径
先和业务确认：一级指标（运营成功率/满意度/日活）怎么算、二级驱动指标怎么取数、数据来源在哪，先保证口径统一——不然后面所有分析与优化都建立在不可比的数据上。
2. 用数据定位"头部问题"，先讲清怎么找
不是所有问题都值得先优化，要抓"影响最大、最集中"的那几个（二八）。我会先列三个维度，再交叉看：
故障类型
哪类问题——回充失败 / 电机堵转 / 贴边漏扫等，先按类型归并。
发生频率
每类问题多久出现一次，量化影响面大小。
集中度
集中在某些设备批次，还是某些时段——判断是设备问题还是环境问题。
三个维度交叉后，自然能筛出最拖累一级指标的那几个"头部问题"，再沿二级驱动往下归因。
3. 把问题变成产品改进
把归因结果梳理成可落地的产品/研发需求（MRD），跟进到真正推动迭代——这是闭环的最后一步，也是"为头部指标健康度负责"的落点。
4. 用自动化把这件事做起来
自研的 AI 数据分析工作流（数据→分析→报告→推送）可以复用；SQL/Python/BI 指标口径与看板功底也都在。

希望和团队一起，把设备在客户现场的运营，变成一套看得清、能优化的指标体系
